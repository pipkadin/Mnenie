# Система изучения общественного мнения

Настольное приложение для управления опросами и анализа общественного мнения.

## Технологии

- **Python 3** - язык программирования
- **PostgreSQL** - система управления базами данных
- **Tkinter (ttk)** - графический интерфейс
- **psycopg2** - драйвер для работы с PostgreSQL

## Требования

- Python 3.8 или выше
- PostgreSQL 12 или выше
- pip (менеджер пакетов Python)

## Установка и настройка

### 1. Создание виртуального окружения

```bash
# Windows
python -m venv venv
venv\Scripts\activate

# Linux/Mac
python3 -m venv venv
source venv/bin/activate
```

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 3. Настройка базы данных PostgreSQL

1. Создайте базу данных:
```sql
CREATE DATABASE opinion_survey;
```

2. Выполните SQL-скрипты в следующем порядке:
```bash
# Подключитесь к БД
psql -U postgres -d opinion_survey

# Или используйте графический клиент (pgAdmin, DBeaver и т.д.)
```

Выполните скрипты в порядке:
- `db/01_schema.sql` - создание схемы БД (таблицы, ограничения)
- `db/02_sequences.sql` - создание sequences для PK
- `db/03_functions.sql` - создание функций PL/pgSQL
- `db/04_triggers.sql` - создание триггеров
- `db/05_seed.sql` - тестовые данные (опционально)

Или выполните все скрипты одной командой:
```bash
psql -U postgres -d opinion_survey -f db/01_schema.sql
psql -U postgres -d opinion_survey -f db/02_sequences.sql
psql -U postgres -d postgres -d opinion_survey -f db/03_functions.sql
psql -U postgres -d opinion_survey -f db/04_triggers.sql
psql -U postgres -d opinion_survey -f db/05_seed.sql
```

### 4. Настройка переменных окружения

Скопируйте файл `env.example` в `.env` и укажите параметры подключения к БД:

```bash
# Windows
copy env.example .env

# Linux/Mac
cp env.example .env
```

Отредактируйте `.env`:
```
DB_HOST=localhost
DB_PORT=5432
DB_NAME=opinion_survey
DB_USER=postgres
DB_PASSWORD=ваш_пароль
```

## Функциональность

### Управление опросами
- Создание, редактирование, удаление опросов
- Активация и закрытие опросов
- Автоматическое продление срока при недостатке ответов (триггер)

### Управление вопросами
- Создание вопросов для опросов
- Добавление вариантов ответов
- Настройка положительных/отрицательных ответов

### Управление респондентами
- Регистрация респондентов
- Хранение демографических данных
- Анонимность: ФИО не отображается в отчётах

### Прохождение опросов
- Выбор опроса и респондента
- Последовательное прохождение вопросов
- Защита от повторных ответов

### Отчёты
- **a)** Список всех опросов с количеством участников
- **b)** Распределение ответов по вопросам
- **c)** Динамика изменения отношения к теме (по неделям)
- **d)** Статистика участия респондентов
- **e)** Средний возраст участников по опросам
- **f)** Опросы с долей положительных ответов > 70%
- **g)** XML-отчёт по опросу

## Особенности реализации

### База данных

- **БКНФ**: Все таблицы нормализованы, нет избыточных зависимостей
- **Sequences**: PK генерируются через явные sequences (не SERIAL/IDENTITY)
- **Триггер**: Автоматическое продление опроса при недостатке ответов
- **Функция**: Генерация XML-отчётов
- **Анонимность**: Отчёты не содержат ФИО респондентов

### Безопасность

- Параметризованные SQL-запросы (защита от SQL-инъекций)
- Валидация данных на уровне БД (CHECK constraints)
- Уникальные ограничения для предотвращения дублирования

### Архитектура

- Разделение на слои: UI, репозитории, БД
- Использование только нативных SQL (без ORM)
- Контекстные менеджеры для транзакций
- Обработка ошибок с дружелюбными сообщениями

## Обоснование БКНФ

Все таблицы находятся в БКНФ (Бойса-Кодда нормальной форме):

1. **surveys**: Все атрибуты зависят только от PK (id)
2. **questions**: Зависят от PK, survey_id - FK (нет транзитивных зависимостей)
3. **answer_options**: Зависят от PK, question_id - FK
4. **respondents**: Все атрибуты зависят только от PK
5. **responses**: Композитный уникальный ключ предотвращает дублирование
6. **population_categories**: Независимая таблица
7. **respondent_categories**: Таблица связи M:N (композитный PK)

Нет денормализации, нарушающей БКНФ.

## Триггер продления опроса

Триггер `trigger_extend_survey_before_close` срабатывает при попытке закрыть опрос:

- Если ответов 0: срок удваивается
- Если ответов меньше min_required_answers: срок продлевается пропорционально дефициту
- Опрос остаётся активным до получения достаточного количества ответов

## Примечания

- Для работы с датами используется простой ввод в формате YYYY-MM-DD
- Все отчёты ограничены 50 строками для производительности
- XML-отчёты сохраняются через диалог выбора файла
- Тестовые данные в `05_seed.sql` можно использовать для демонстрации

## Устранение неполадок

### Ошибка подключения к БД
- Проверьте параметры в `.env`
- Убедитесь, что PostgreSQL запущен
- Проверьте права доступа пользователя БД

### Ошибки при выполнении SQL
- Убедитесь, что скрипты выполнены в правильном порядке
- Проверьте версию PostgreSQL (требуется 12+)

### Проблемы с интерфейсом
- Убедитесь, что установлены все зависимости: `pip install -r requirements.txt`
- Проверьте версию Python (требуется 3.8+)
